---
title: "Resolution Events"
description: "Events exchanged during outcome and paradox resolution"
---

Resolution lifecycle events are produced by `timeline-service`. Player paradox submissions and scoring updates
are published by `game-service` on `game.events`. Probability bands are published only by timeline-service.

## ResolutionStarted 🌐

```json
{ "gameId": "uuid", "eraNumber": 1 }
```

## ProbabilityStateCalculated 📢

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "eventStates": [{
    "eventId": "uuid",
    "outcomes": [
      { "outcomeId": "uuid", "probability": 56, "isAnnihilated": false, "isSealed": false },
      { "outcomeId": "uuid", "probability": 44, "isAnnihilated": false, "isSealed": false },
      { "outcomeId": "uuid", "probability": 0,  "isAnnihilated": true,  "isSealed": false }
    ]
  }]
}
```

Era-level, emitted once at resolution, and **never delivered to any player**. Each probability is the outcome's real
chance of winning, so an annihilated outcome always reports 0. It exists for downstream resolution and
history. Exact probabilities reach players only through `ProbabilityStateRevealed`, below.

## ProbabilityStateRevealed 🔒

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "roundNumber": 2,
  "playerId": "uuid",
  "eventId": "uuid",
  "outcomes": [
    { "outcomeId": "uuid", "probability": 56, "isAnnihilated": false, "isSealed": false },
    { "outcomeId": "uuid", "probability": 44, "isAnnihilated": false, "isSealed": false },
    { "outcomeId": "uuid", "probability": 0,  "isAnnihilated": true,  "isSealed": false }
  ]
}
```

The payout for a `SCAN`. `playerId` is the **scanning** player, and the message goes to them alone — one message per
scanned event, so a Scan on one event never discloses another.

Scan is live for the rest of the era: a reveal is published at the close of the round it was played and at every
subsequent round close, so the values stay current while other players wait for bands. `roundNumber` stamps when the
values were observed. Scans do not carry into the next era.

## AdjustedBandsPublished 🌐

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "eventStates": [{
    "eventId": "uuid",
    "outcomes": [
      { "outcomeId": "uuid", "band": "HIGH" },
      { "outcomeId": "uuid", "band": "MEDIUM" },
      { "outcomeId": "uuid", "band": "LOW" }
    ]
  }]
}
```

Published exactly once per era by `timeline-service` on `timeline.events` after Round 2's full replay. This is the
only public band publication: it includes resolved modifiers and carried weights. `LOW` covers 0–30%, `MEDIUM`
31–60%, and `HIGH` 61–90%, using configured thresholds. Exact values remain private to Scan-entitled players.

Game-service records this fact for the current era before requesting Action Round 3. If it is delayed, Round 3
and its timer wait. Readiness survives restart and either arrival order relative to the Round 2 close listener;
duplicate or stale-era facts cannot open another round. The name describes probabilities adjusted by resolved
effects; no preview precedes it.

## ParadoxDetected 🌐

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "paradoxes": [{
    "paradoxId": "uuid",
    "type": "DEAD_HEAT",
    "affectedEventId": "uuid",
    "affectedOutcomeIds": ["uuid", "uuid"],
    "description": "string"
  }]
}
```

`type` is `DEAD_HEAT`, `IMPOSSIBLE_ERASURE`, or `CHAIN_CONFLICT`. `description` names the paradox and its affected
event and outcomes only; no field carries a probability value.

## ParadoxResolutionPhaseStarted 🌐

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "paradoxIds": ["uuid"],
  "timerSeconds": 60
}
```

## ParadoxResolutionCardsOffered 🔒

Published once per player per paradox-resolution phase, when the phase opens. A player who was not yet known when
it opened receives theirs on joining the open phase. Private to `playerId`.

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "playerId": "uuid",
  "cards": [
    { "cardInstanceId": "uuid", "cardType": "PUSH", "grade": "II" },
    { "cardInstanceId": "uuid", "cardType": "STABILIZE", "grade": "I" },
    { "cardInstanceId": "uuid", "cardType": "DETONATE", "grade": "I" }
  ]
}
```

`cards` is every card the player may submit in the phase: eligible cards from their hand plus the Stabilize and
Detonate they are dealt for it. An empty list is valid.

## ParadoxResolutionCardPlayed 🔒

Published by `game-service`'s action module to `game.events`; consumed by `timeline-service`. It is never published on
`timeline.events` and is never forwarded to players.

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "playerId": "uuid",
  "cardInstanceId": "uuid",
  "cardType": "STABILIZE",
  "grade": "I",
  "targetEventId": "uuid",
  "targetOutcomeId": "uuid"
}
```

No faction special actions are allowed during paradox resolution. Eligible cards are `PUSH`, `SUPPRESS`, `STABILIZE`,
and `DETONATE`; the phase-scoped event has no `roundNumber`. `grade` is always present; single-grade cards carry `I`.

## ParadoxResolutionPassed 🔒

Published after a player explicitly passes during an open paradox-resolution phase. Private to that player.

```json
{ "gameId": "uuid", "eraNumber": 1, "playerId": "uuid" }
```

The payload carries no card or target. A pass uses the player's one choice for the phase, counts toward closing it
early, and applies nothing — the same neutral skip a timer expiry produces.

## ParadoxResolved 🌐

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "paradoxId": "uuid",
  "resolvedByPlayerIds": ["uuid"]
}
```

`resolvedByPlayerIds` lists the players credited with clearing the paradox: everyone whose `STABILIZE` targeted
the event when any did, otherwise everyone whose `PUSH` or `SUPPRESS` targeted it. Each player appears once, ordered
by player id, so the list never depends on submission order. A Stabilize-cleared event resolves by the ordinary
weighted draw over its unchanged weights.

## ParadoxCascaded 🌐

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "paradoxId": "11111111-1111-4111-8111-111111111111",
  "paradoxIds": [
    "11111111-1111-4111-8111-111111111111",
    "22222222-2222-4222-8222-222222222222"
  ],
  "affectedEventId": "uuid",
  "carryForwardProbabilityState": [
    { "outcomeId": "uuid", "probability": 50 },
    { "outcomeId": "uuid", "probability": 50 },
    { "outcomeId": "uuid", "probability": 0 }
  ],
  "detonatedByPlayerIds": ["uuid"]
}
```

One `ParadoxCascaded` is published per affected event, even when several paradox findings remain. `paradoxIds`
lists every finding still present; `paradoxId` is its first member for consumers of older facts. The array is
absent on older facts. A finding that clears receives `ParadoxResolved`; a finding first detected during the
resolution phase is announced by `ParadoxDetected` before it appears in this array. The era terminal barrier
lists that event once as `CASCADED`.

`detonatedByPlayerIds` lists every player, if any, whose `DETONATE` card targeted this event-level cascade —
empty when none did. Multiple `DETONATE`s on the same event don't stack. This is a fact only; the doubled score
penalty for every other player and the base penalty for each detonator are applied by scoring, once per cascaded event.

## CorruptInversionConfirmed 🔒

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "roundNumber": 2,
  "corruptingPlayerId": "uuid",
  "targetEventId": "uuid",
  "targetOutcomeId": "uuid",
  "tookEffect": true
}
```

Service-coordination data, not a standalone player notification. Confirms whether a round's `CORRUPT` actually
inverted its target card's effect, or was blocked by a same-round `SEAL` (`tookEffect: false`).

## AnnihilationResolved 🔒

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "roundNumber": 1,
  "annihilatingPlayerId": "uuid",
  "targetEventId": "uuid",
  "targetOutcomeId": "uuid",
  "erased": true,
  "wasLeading": true
}
```

Service-coordination data, not a standalone player notification. Reports what one non-cancelled `ANNIHILATE` did
once its round resolved: `erased` is `true` when the target was still in contention, and `wasLeading` is `true` when
it held the highest probability among the event's remaining outcomes, ties included. Both are judged before that
round's Annihilates take effect, so submission order within the round changes neither. Scoring credits the
Annihilate only when both are `true`.

## CascadeCarriedForward 🌐

```json
{
  "gameId": "uuid",
  "eraNumber": 2,
  "targetEventId": "uuid",
  "targetOutcomeId": "uuid"
}
```

A `CASCADE` armed in the previous era re-erased this outcome at the start of this era — the only automatic,
cross-era faction effect. Published only for an event that carried into this era through Stall or a paradox
cascade. Applies at most once per `CASCADE`.

## ResolutionFailed 🔒

```json
{

  "eraNumber": 1,
  "affectedEventId": "uuid",
  "reason": "PROBABILITY_SUM_INVALID"

```

Internal-only: signals an invalid probability state after resolution. Not expected in normal play.

## EraResolutionCompleted 🔒

This is service-coordination data, not a standalone player notification. Timeline emits it exactly once after all
resolvable `OutcomeApplied` and `ParadoxCascaded` facts for the era. A `STALL` card places its selected event in the
barrier as `STALLED`; it emits neither an outcome fact nor a paradox fact. A paradox-resolution timeout instead
force-cascades unresolved paradoxes. Entries are in the original `EventsDrawn.events` reveal order, including
carried-over events.

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "terminalResolutions": [
    { "eventId": "uuid", "revealIndex": 0, "terminalState": "OUTCOME_APPLIED", "winningOutcomeId": "uuid" },
    { "eventId": "uuid", "revealIndex": 1, "terminalState": "STALLED" }
  ]
}
```

`revealIndex` and array index match the zero-based position in `EventsDrawn.events`; producers and consumers validate
that every active event appears exactly once in that order. Session uses `CASCADED` entries to decide whether the
era collapses the timeline, carries both `CASCADED` and `STALLED` entries into the next era, and keeps a stalled event out of
collapse accounting. Scoring finishes either non-applied state without waiting for an outcome that cannot arrive.
`STALLED` expires origin-era Activist and Prophet predictions without a score. A matching pending Weaver Thread is
invalidated without penalty; a later bet on the carried event has a new era origin.

## ScoresUpdated 📢

```json
{
  "gameId": "uuid",
  "eraNumber": 1,
  "updates": [{
    "playerId": "uuid",
    "faction": "PROPHETS",
    "pointsDelta": 4,
    "reason": "EVENT_RESOLVED_AS_WRITTEN",
    "newTotal": 12
  }]
}
```

`read-service` reshapes this per connected viewer before delivery: an `updates` entry keeps `faction` and
`reason` only for the session belonging to that entry's `playerId`. Every other session receives the same
entry with both fields removed — `playerId`, `pointsDelta`, and `newTotal` stay visible to everyone.
