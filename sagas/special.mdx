## WeaverChainSaga

**Trigger:** `SpecialActionPlayed` where `specialAction = THREAD`, judged when its round closes  
**Service:** `timeline-service`

The only saga spanning multiple eras — remains open across era boundaries until completed, broken, or the game
ends. A `THREAD` play names one not-yet-resolved current-era outcome as the chain's newest link. That link is
**pending** until it resolves — see [Weaver Chain Events](/events/weaver-chain) for the full event set.

`THREAD`, `TAPESTRY`, and `REWEAVE` resolve with the rest of their round (see the
[card effect application order](/sagas/resolution#card-effect-application-order)), so a Nullify naming the Weaver in
that round cancels them outright.

### Steps

```mermaid
flowchart TD
  A[THREAD special played — judged at round close] --> B{Valid current-era, not-yet-resolved coordinate; no pending link already open?}
  B -->|Invalid| C[reject submission — emit ThreadRejected]
  B -->|Valid| D[emit ChainLinkThreaded — pending link created, favorable push joins the round's simultaneous tier]
  D --> E{Pending link resolves}
  E -->|Predicted outcome drawn as winner| F[emit ChainLinkAdded — chainLength++]
  E -->|Another outcome wins| G[emit ChainLinkInvalidated — no penalty]
  E -->|Event Stalls or cascades| G
  E -->|Annihilated, Tapestry armed| H[emit ChainProtectionConsumed, then ChainLinkInvalidated]
  E -->|Annihilated, unprotected| I[raise CHAIN_CONFLICT paradox]
  I -->|Resolved — chain intact, erased outcome can't win| G
  I -->|Cascaded| J[emit ChainBroken — saga ends; next THREAD starts a new chain]
  F --> K{chainLength == 3?}
  K -->|Yes| L[emit ChainCompleted — saga ends]
  K -->|No| M[Saga stays open — wait for next THREAD]
```

### Era boundary handling

| Event | Outcome |
|---|---|
| `TAPESTRY` played (chain ≥ 2, not yet used this era) | Arm protection for the pending link, for the rest of this era — emit `ChainProtectionArmed` |
| `REWEAVE` played (once per era) | Move the current-era pending link to a different live current-era outcome — emit `ChainReAnchored`, length unchanged, link still pending; never completes the chain |
| Pending link's event Stalls or cascades | Emit `ChainLinkInvalidated` in that era; confirmed links stay and a later Thread is a new prediction |
| Unresolved `CHAIN_CONFLICT` paradox | Emit `ChainBroken`, saga ends — the chain's only reachable break trigger |
| `GameEnded` with chain < 3 | Invalidate any pending link and end the incomplete chain without a bonus |
| `GameEnded` with chain ≥ 3 | `ChainCompleted` already fired before `GameEnded` |

## PlayerReconnectSaga

**Trigger:** Player WebSocket disconnects during an active game
**Service:** `game-service` / session module

Each player has one active grace period. Duplicate disconnect delivery reuses its deadline; a later disconnect
after reconnect creates a new period. Reconnect is accepted only strictly before that deadline.

### Steps

```mermaid
flowchart TD
  A[WebSocket disconnect] --> B[Mark player DISCONNECTED — emit PlayerDisconnected 🌐]
  B --> C[Start grace timer — default 30s, configurable via GameRulesPort]
  C --> D{Player reconnects?}
  D -->|Yes — within grace period| E[Mark player reconnected]
  D -->|No — deadline expires| F[Reconcile every due grace period — emit PlayerAbandoned 🌐 for each forfeit]
  F --> Q{Era scoring in flight?}
  Q -->|Yes| K[Wait for committed totals and reconcile deadlines again]
  K --> G{Eligible contenders remaining?}
  Q -->|No| G
  G -->|One| H[WinConditionMet 🌐 LAST_PLAYER_STANDING — EndGameSaga]
  G -->|Zero| J[GameEndedAbnormally 🌐 all-players-abandoned — EndGameSaga]
  G -->|More than one| I[Continue game]
```

This saga only tracks `game-service`'s connection bookkeeping. State restoration itself isn't one of its steps: a
reconnecting client opens a new `read-service` WebSocket connection, and `read-service` pushes a fresh game-state
snapshot on every connection it accepts — see [Reconnection](/api/websocket#reconnection) — independently of
whether this saga's grace period is still open.

### Compensation

| Failure | Compensation |
|---|---|
| Player reconnects after `ABANDONED` | Reject reconnection — game already adapted |
| Equal or staggered deadlines have all expired | Reconcile all due periods before choosing contenders; zero contenders ends with no winner and all final scores |
| Grace expires after the game ended | Nothing happens — the player is not marked abandoned and nothing is published |
| One or zero contenders while the era is being scored | Wait for committed scores, then recheck all deadlines; an expired contender cannot win |
| Reconnect arrives after its deadline | Reject it even if the timer callback has not run |
| In-memory timer is lost | The database sweep processes persisted due deadlines on a surviving instance |

When zero contenders remain, `GameEnded` uses `ALL_PLAYERS_ABANDONED`, no winner fact is emitted, every final
score is retained, and factions are revealed normally. An eligible normal-victory qualifier at the scoring boundary
keeps precedence over last player standing. A grace expiry after game end retires its timer state without changing
the roster or publishing a new abandonment.
