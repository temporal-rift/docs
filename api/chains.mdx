---
title: "Chains API"
description: "Gated Weaver chain read served by timeline-service"
---


Restricted chain query served by `timeline-service` — its only REST endpoint. This endpoint exposes only the
requesting player's own Weaver chain, including its `links` and per-Weaver progress. The read service separately
exposes the current chain's `status` and `length` to every player without identifying which player owns or broke
the chain.

## Get own chain

```http
GET /api/v1/games/{gameId}/chains
```

**Response `200`:**
```json
{
  "chainId": "uuid",
  "status": "ACTIVE",
  "chainLength": 2,
  "links": [
    { "eventId": "uuid", "outcomeId": "uuid", "eraNumber": 1 },
    { "eventId": "uuid", "outcomeId": "uuid", "eraNumber": 2 }
  ]
}
```

`status` is `ACTIVE`, `COMPLETED`, or `BROKEN`. When a Weaver rebuilds after a break, the open chain is
returned; with no open chain, the longest terminal one.

| Error | Code | Condition |
|---|---|---|
| `403` | `403-01` | Requesting player is a participant but not the Weavers faction |
| `404` | `404-01` | Game not found, or requesting player is not a participant (indistinguishable; checked before faction, so non-participants always get `404-01`) |
| `404` | `404-02` | Requesting Weaver has no chain yet |
