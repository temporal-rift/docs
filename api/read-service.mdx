---
title: "Read Service API"
description: "Game state, history, and probability query endpoints"
---

`read-service` serves denormalized, per-player views of game state. This is the primary endpoint clients use on load and reconnect.

## Get full game state

```http
GET /api/v1/games/{gameId}/state
```

Full per-player view — no raw probabilities, no other players' factions.

**Response `200`:**
```json
{
  "gameId": "uuid",
  "eraNumber": 2,
  "revision": 41,
  "lastUpdatedAt": "2026-09-16T00:00:00Z",
  "phase": "ACTION_ROUND_2",
  "roundNumber": 2,
  "deadlines": {
    "handSelectionExpiresAt": null,
    "actionRoundExpiresAt": "2026-09-16T00:01:00Z",
    "paradoxResolutionExpiresAt": null
  },
  "phaseContext": {
    "declarationOpen": false,
    "paradoxOpen": false
  },
  "myFaction": "ERASERS",
  "myHand": [
    { "cardInstanceId": "uuid", "cardType": "PUSH", "grade": "II", "isPlayableThisRound": true },
    { "cardInstanceId": "uuid", "cardType": "SCAN", "grade": "I", "isPlayableThisRound": false }

      "activistPlayerId": "uuid",

```

Every active event has required `carryOverState`: `FRESH`, `CASCADED`, or `STALLED`. `playerName` is reserved for a
later slice and is currently `null`. Every field after `players` except `lastRoundSummary` and `chain` is optional:
absent means not yet computed by the owner, while an empty array means known-none. Refresh this view after reload or
a rejected submission and retry at most once against the fresh era/round/deadline coordinates.

<Note title="Faction visibility">
`faction` on other players is `null` until `FactionRevealed` fires at game end. Your own faction is always visible in `myFaction`.
</Note>

<Note title="Weaver chain visibility">
`chain` shows the current Weaver chain's `status` (`ACTIVE`/`COMPLETED`/`BROKEN`) and `length` identically to every
player. It is `null` until a chain exists and clears once the game ends. It never identifies which player owns or
broke the chain, before or after `FactionRevealed`.
</Note>

### Hand fields

`grade` is always present — single-grade cards carry `I`. `isPlayableThisRound` tells the client which cards to grey
out; it changes as rounds advance without a new hand being dealt.

While the current-era hand choice is open, the response additionally contains a private `pendingHandSelection`:

```json
{
  "cards": [
    { "cardInstanceId": "uuid", "cardType": "PUSH", "grade": "II", "dealSlot": 1 }
  ],
  "requiredSelectionCount": 5,
  "expiresAt": "2026-08-13T20:00:00Z"
}
```

The top-level state `phase` is `HAND_SELECTION` throughout this window; the server, not the browser, decides when the deadline expires and which five cards remain after a timeout.

It contains exactly seven cards in deal-slot order. During this window `myHand` remains the final playable hand, not
the temporary selection pool. Once the player selects five cards—or the server makes a uniform random timeout
selection—the field disappears and `myHand` contains those five cards.

### Jam status

`myJammedUntilRound` is private to the authenticated player. It is `null` when that player is not jammed and otherwise
contains the round through which faction specials are blocked. The value clears after that round passes and never
carries across an era boundary. Jam does not prevent the player from playing cards.

### Revealed intel

`myRevealedIntel` is always present. It holds what you have bought with Information cards **this era**, is `[]` when
you have bought none, and is emptied when the era ends. Each entry carries `observedInRound` so the client can show
how fresh it is.

| `kind` | From | Contents |
|---|---|---|
| `PROBABILITY` | Scan | exact outcome values for one event, refreshed every round until era end |
| `INFLUENCE` | Trace | which players acted on one event last round |
| `HAND_CARD` | Intercept | a card seen in another player's hand |

<Note title="This is the only source of exact probabilities">
Scan results reach you here and over the WebSocket — there is no probability endpoint. Every other player sees only
Low/Medium/High bands after Action Round 2.
</Note>

### Freshness, deadlines, and retry

`revision` is a monotonic freshness marker for one game's projection: a larger value means a newer view. It orders
polls of the same game and never promises cross-game or cross-topic event order. `roundNumber` names the current
round while an action round or paradox resolution is open and is `null` otherwise. `deadlines` carries the
authoritative expiry timestamps owned by `game-service`, and `phaseContext` tells you which windows currently accept
input (`declarationOpen` for Rally/Momentum before Round 1, `paradoxOpen` for reactive cards, with `paradoxIds`
listing the open paradoxes — present only while `paradoxOpen` is true, absent otherwise).

After reload, a delayed response, or a rejected submission, refresh this view and retry at most once against the fresh
coordinates instead of retrying blindly.

### Public bands, declarations, and Expose facts

`publicBands` holds the approximate Low/Medium/High bands published after Action Round 2, each entry carrying the
round it was observed in so the client can show its age. Exact probabilities never appear here — only in your own
`myRevealedIntel`. The adjusted publication supersedes the preview for the same game and era; the field replaces,
never duplicates, it.

`declarations` lists the current era's public Rally/Momentum declarations of record, and `exposeFacts` lists the
public Expose outcomes: the exposed Round-1 signature plus whether the target's behavior changed in Round 3. No
Round-3 signature is ever included. `signature.sourceOutcomeId` is populated only for `SWING` signatures.

### Your submissions, budgets, and objective progress

`mySubmissions` names your own accepted decisions (`HAND_SELECTION`, `DECLARATION`, `ACTION`, `PARADOX_CARD`) so a
reloaded client can show what was accepted without asking twice. `mySpecialBudgets` lists remaining per-era and
per-game uses for your own specials, including Seal. Neither field ever carries another player's choices or
availability.

`myObjectiveProgress` is your own cumulative progress toward your faction objective: `progressCount` against an
owner-populated `threshold`, plus `objectiveMet`. Use the transmitted threshold rather than a hard-coded constant.
For Weavers the count mirrors the public chain length; every other faction's count is private to you.

### Terminal result

Once `phase` is `GAME_ENDED`, `result` carries the authoritative terminal facts: `endReason`, the `winners` set,
`finalScores`, and the `revealBoundary` declaring what is now public to participants
(`FACTIONS_AND_SCORES_PUBLIC`). Per-round private hands and intel stay caller-scoped even after the game ends.

## Get full game history

```http
GET /api/v1/games/{gameId}/history
```

Full era-by-era history of resolved outcomes and paradoxes, plus your own dealt hand for each era — useful for
catching up after a disconnect that spans an era transition, since the live `/state` endpoint only ever shows the
current era's hand.

**Request:**

`gameId` is a UUID path parameter identifying the game. The request must carry `Authorization: Bearer <jwt>`; the
player identity is derived from the validated token (see the API reference overview). A missing, invalid, or expired
token returns `401`.

**Response `200`:**
```json
{
  "gameId": "uuid",
  "eras": [
    {
      "eraNumber": 1,
      "outcomes": [
        { "eventId": "uuid", "title": "string", "winningOutcomeId": "uuid", "winningOutcomeDescription": "string" }
      ],
      "paradoxesCascaded": 0,
      "myHand": [
        { "cardInstanceId": "uuid", "cardType": "PUSH", "grade": "II", "dealSlot": 1 }
      ]
    },
    {
      "eraNumber": 2,
      "outcomes": [],
      "paradoxesCascaded": 1,
      "cascadedEvents": [
        { "eventId": "uuid", "title": "string" }
      ],
      "myHand": []
    }
  ]
}
```

`eras` is ordered by ascending `eraNumber`. Each era's `outcomes` holds one entry per resolved event — `eventId`,
`title`, `winningOutcomeId`, and `winningOutcomeDescription` — in the order the events were revealed.
`paradoxesCascaded` counts the paradoxes that cascaded in that era. `cascadedEvents` lists the affected events
(`eventId` plus `title`) in reveal order; it is omitted when `paradoxesCascaded` is `0` and present otherwise.

`myHand` holds the authenticated caller's final five-card hand for that era — the kept selection (or the timer's
default when the selection window expired), not the seven-card deal pool. It is always present and `[]` when the
caller has no recorded hand for the era. Each card carries `cardInstanceId`, `cardType`, `grade` (always present —
single-grade cards carry `I`), and `dealSlot` (`1`–`7`, the card's position in the original deal).

<Note title="myHand is private to you">
Every field on this endpoint except `myHand` is shared across all players in the game. `myHand` only ever contains
cards dealt to you — never another player's hand, past or present.
</Note>

| Error | Condition |
|---|---|
| `401` | Missing, invalid, or expired bearer token |
| `404` | No history exists for this game — unknown game or no era has been recorded yet |

Both error responses use `application/problem+json` Problem Details bodies.

**Response `404` (`application/problem+json`):**
```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "Game history not found for game 3fa85f64-5717-4562-b3fc-2c963f66afa6"
}
```
