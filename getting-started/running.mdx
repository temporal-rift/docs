---
title: "Running the services"
description: "Start game-service, timeline-service, and read-service locally with the dev profile"
---

All three services — `game-service`, `timeline-service`, and `read-service` — have runnable code and can be started
individually outside Docker Compose with the `dev` profile.

## Environment variables

| Variable | Default (dev profile) | Required in prod |
|---|---|---|
| `SPRING_DATASOURCE_HOST` | `localhost` (baked into the JDBC URL) | ✔ |
| `SPRING_DATASOURCE_PORT` | `5432` (baked into the JDBC URL) | ✔ |
| `SPRING_DATASOURCE_NAME` | `temporal_rift` (baked into the JDBC URL) | ✔ |
| `SPRING_DATASOURCE_USERNAME` | `temporal_rift` | ✔ |
| `SPRING_DATASOURCE_PASSWORD` | `temporal_rift` | ✔ |
| `KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` | ✔ |
| `KAFKA_SECURITY_PROTOCOL` | `PLAINTEXT` | ✔ |
| `JWT_ISSUER_URI` | `http://localhost:9000/default` for `game-service`; **not defaulted** for `timeline-service` or `read-service` — must be supplied even in dev | ✔ |
| `PORT` | `8080` | — |

All three services are OAuth2 resource servers. `http://localhost:9000/default` is the interactive test issuer the
local Compose stack runs (see [Local Infrastructure](/getting-started/local-infrastructure)); start at least that
container before calling authenticated endpoints.

<Warning>
All three services default to `PORT` `8080`. Docker Compose maps them to distinct host ports (8080/8081/8082 — see
[Local Infrastructure](/getting-started/local-infrastructure)), but running them standalone with `mvn
spring-boot:run` does not: start more than one without setting `PORT` explicitly and the second and third will fail
to bind.
</Warning>

## Start with dev defaults

The `dev` profile fills in database and Kafka connection details for all three services — for `game-service` it
also fills in `JWT_ISSUER_URI`. `timeline-service` and `read-service` still require `JWT_ISSUER_URI` to be set even
under `dev`.

```bash
mvn -f game-service/pom.xml spring-boot:run -Dspring-boot.run.profiles=dev

PORT=8081 JWT_ISSUER_URI=http://localhost:9000/default mvn -f timeline-service/pom.xml spring-boot:run -Dspring-boot.run.profiles=dev

PORT=8082 JWT_ISSUER_URI=http://localhost:9000/default mvn -f read-service/pom.xml spring-boot:run -Dspring-boot.run.profiles=dev
```

## Artifact publication order

When publishing to Maven Central for the first time, order matters:

<Steps>
  <Step title="build-tools">
    Shared Checkstyle and Spotless configuration
  </Step>
  <Step title="temporal-rift-bom">
    Parent POM and plugin management
  </Step>
  <Step title="apis">
    Spec-first event (AsyncAPI) and REST (OpenAPI) contracts, code-generated per service
  </Step>
  <Step title="Service artifacts">
    game-service, timeline-service, read-service
  </Step>
</Steps>

The `temporal-rift-bom` CI workflow publishes `build-tools` and the BOM in a single job in the correct order.
