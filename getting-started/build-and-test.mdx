## Running tests

```bash
# All tests (unit + integration via Testcontainers)
mvn -f game-service/pom.xml test

# Single test class
mvn -f game-service/pom.xml test -Dtest="LobbyTest"

# Architecture tests only
mvn -f game-service/pom.xml test -Dtest="*ArchitectureTest"

# Integration test (Testcontainers PostgreSQL + Kafka + Modulith verify)
mvn -f game-service/pom.xml test -Dtest="GameServiceApplicationIT"
```

## Test categories

| Category | Naming convention | Spring context | Infrastructure |
|---|---|---|---|
| Unit tests | `{Subject}Test` | None | None |
| Slice tests | `{Module}ModuleTest` | `@ApplicationModuleTest` | None |
| Integration test | `GameServiceApplicationIT` | Full | Testcontainers |
| Architecture tests | `*ArchitectureTest` | None | None |

`GameServiceApplicationIT` starts real PostgreSQL and Kafka via Testcontainers and runs `ApplicationModules.verify()` to assert Spring Modulith module boundaries.

## Code quality gates

Both run automatically on every build via the `validate` phase:

<CodeGroup>
```bash Check formatting
mvn -f game-service/pom.xml spotless:check
```

```bash Fix formatting
mvn -f game-service/pom.xml spotless:apply
```

```bash Checkstyle
mvn -f game-service/pom.xml checkstyle:check
```

```bash Run both
mvn -f game-service/pom.xml validate
```
</CodeGroup>

## Contract publishing

REST and event contracts live in the **`apis`** repo as independently versioned, spec-only Maven artifacts. AsyncAPI
modules (`session-event`, `action-event`, `scoring-event`, `timeline-event`) and OpenAPI modules (`session-api`,
`action-api`, `scoring-api`, `projection-api`) publish the specifications. `temporal-rift-bom` unpacks contract
resources during `initialize` into an artifact-isolated build directory, so services only declare their dependencies and
generate the producer, consumer, or REST-interface artifacts their workflow supports. No service keeps a duplicate
contract copy.

```bash
# 1. Bump version in apis/<module>/pom.xml and merge to main
# GitHub Actions publishes automatically to Maven Central

# 2. After Central publishes it, update the consuming service dependency version and test
mvn -f game-service/pom.xml test
```

<Warning>
**Never use `mvn install` or manually run `mvn deploy` for shared artifacts.** Local publication makes builds
non-reproducible. Merge the version bump to `apis` `main` and let its publishing workflow release the artifact.
</Warning>
